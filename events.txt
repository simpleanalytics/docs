# Collect events with Simple Analytics

How to collect events, like signups and button clicks, with Simple Analytics and check that they work. Written for AI agents, like Claude Code, Codex and Cursor, and for developers.

Came here from the Simple Analytics dashboard or its MCP tools? They gave you the hostname and the script host of the website, use those.

## 1. Before you start

- Events in the browser need the Simple Analytics script on every page. Not there yet? Follow [the install guide]({{ site.url }}/install.md) first. Events from a server or app don't need the script, see option 4 below.
- Load event scripts the same way as the main script: from the same custom domain or proxy. Does the script have a [`data-namespace`]({{ site.url }}/events#the-variable-sa_event-is-already-used), like `data-namespace="ba"`? Then the function is `ba_event` instead of `sa_event`.
- Look for events the website already sends, like `sa_event` calls and `data-simple-event` attributes, so you don't send them twice.

## 2. Send events

Use the first option that covers the event:

1. **Outbound links, downloads, email and phone links:** add the [automated events script]({{ site.url }}/automated-events) next to the main script. No code needed. It stores the address or number that's already on the website's link, not what visitors type:

   ```html
   <script async src="https://scripts.simpleanalyticscdn.com/auto-events.js"></script>
   ```

   With a custom domain or the proxy, load it from that domain. With `data-namespace="ba"`, add `data-sa-global="ba_event"` to it.

2. **Clicks and form submissions:** add `data-simple-event="signup_form"` to the element, from script version 12. See [inline events]({{ site.url }}/events/inline).
3. **Everything else,** like a signup that succeeded: call `sa_event` in JavaScript.

   ```js
   sa_event("signup_completed", { plan: "starter" });
   ```

   Events that can happen right after the page loads need the [placeholder function]({{ site.url }}/events#placeholder-event-function) in `<head>`, before other scripts.

4. **From a server or app:** send them to our endpoint, see [server-side events]({{ site.url }}/events/server-side). User agents with `bot`, `spider`, `crawl` or `agent` in them are stored as robots, so use one like `ServerSide/1.0 (+https://www.example.com/)`.

## 3. Name events and add metadata

- **Names:** letters, numbers and underscores, like `signup_completed`. Names are case-sensitive. The script replaces other characters with `_`, server-side names are stored as you send them. See [valid event names]({{ site.url }}/events#valid-event-names).
- **When:** send an event when something happened, like a signup that succeeded, not when someone clicks a button that might fail.
- **Metadata:** add details to an event as [metadata]({{ site.url }}/metadata), like `{ plan: "starter" }`. Values are text, numbers, booleans or dates.
- **No personal data:** never put a visitor's email address, name, ID, what they type or other personal data in an event, metadata, button label or link title. It's not allowed, and the account might be suspended.

## 4. Check that it works

1. **In the browser:** trigger the event and find its `simple.gif` request. Its `simple-analytics-feedback` response header says `Thanks for sending this event!` when it works. Never replay the request with curl or other tools, it adds fake events.
2. **From a server or app:** our endpoint answers `201` with `"ok": true` when it stores the event. Otherwise `message` says what's wrong.
3. With access to Simple Analytics, through its MCP tools or a token the user approved, `get_recent_hits` with `type: "events"` shows the latest events, including robots. Headless browsers, like the ones AI agents use, count as robots, so a test event by an agent only shows up there.
4. `get_events` counts the events that aren't robots per name, and `get_metadata` shows their metadata. On an existing website, new events show up within minutes. On a new website, it can take over an hour.

## 5. Use events

- **[Goals]({{ site.url }}/goals)** count events or funnels of events and pages: `create_goal` with the MCP tools, then `get_goal_results`.
- **The [Events Explorer]({{ site.url }}/events-explorer)** shows events with their metadata, and the [export]({{ site.url }}/export-data) has the raw events: `export_data` with the MCP tools.
- **Event counts are how often an event happened,** not how many people did it.
