# Install Simple Analytics

How to add Simple Analytics, privacy-first analytics, to a website and check that it works. Written for AI agents, like Claude Code, Codex and Cursor, and for developers.

Came here from the Simple Analytics dashboard or its MCP tools? They gave you the hostname and the script for the website, use those.

## 1. Add the script

Add the script to every page, for example just before `</body>`. Replace `example.com` with the hostname of the website, as it's added in Simple Analytics:

```html
<!-- 100% privacy-first analytics -->
<script async data-hostname="example.com" src="https://scripts.simpleanalyticscdn.com/latest.js"></script>
```

Always set `data-hostname`. Page views on localhost and on preview or staging URLs then count for the website, so you can test the script before the website is live. See [overwrite domain name]({{ site.url }}/overwrite-domain-name).

Does the website use a [custom domain]({{ site.url }}/bypass-ad-blockers) for Simple Analytics? Load the script from that domain instead: `https://<custom domain>/latest.js`.

Use the guide or plugin for the platform or framework of the website, with the same hostname. Single-page apps don't need extra code, the script tracks page views when the URL changes. With hash routing (`/#/page`), add `data-mode="hash"`, see [hash mode]({{ site.url }}/hash-mode). Is the platform not listed? Add the script to the template or layout every page uses.

Is the website on the Free plan? It needs to show a [Simple Analytics badge]({{ site.url }}/free-plan-badge), in a footer on every page. Without it, we lock the dashboard data and API of the website after 14 days.

## 2. Content Security Policy

Does the website have a Content Security Policy? Add Simple Analytics to the directives it already has, also to `script-src-elem` when the policy has it:

```
script-src https://scripts.simpleanalyticscdn.com;
connect-src https://queue.simpleanalyticscdn.com;
img-src https://queue.simpleanalyticscdn.com;
```

With a custom domain, allow that domain instead of both. The Free plan badge also needs `img-src https://simpleanalyticsbadges.com`. See [Content Security Policy]({{ site.url }}/csp).

## 3. Check that it works

1. Open a page with the script in a browser and find the `simple.gif` request, in DevTools or with the Chrome DevTools Protocol. Its `simple-analytics-feedback` response header says:
   - `Thanks for sending this page view!`: page views work.
   - `Thanks for sending this event!` or `Thanks for sending this additional data!` (sent when leaving a page): that request works, but also check the page view request.
   - `Website not registered in Simple Analytics, dropping request`: the hostname that was sent isn't added to Simple Analytics, check `data-hostname`.
   - `IP in excluded IP list for website`: the website settings exclude this IP address.
   - Anything else explains what is wrong.
2. No `simple.gif` request? Check the console for `Simple Analytics:` warnings and Content Security Policy errors.
3. Never replay the `simple.gif` request with curl or other tools, it adds fake page views.

JavaScript on the page can't read this header. Server-side page views, like `trackPageview` in Next.js middleware, don't show up in the browser at all.

With access to Simple Analytics, through its MCP tools or a token the user approved, `check_installation` checks the live website and `get_recent_hits` shows the latest page views and events.

Headless browsers, like the ones AI agents use, count as robots. Simple Analytics stores robots but doesn't show them in the dashboard, so a test visit by an agent only shows up in the recent hits, marked as a robot.

If the recent hits show nothing, that doesn't mean the installation failed. A page view that got `Thanks for sending this page view!` is almost always stored, also when the website isn't added yet. Hits of new websites can take over an hour to show up.

## 4. Collect the right data

- **URL parameters:** we only keep UTM codes and `ref`. To collect another parameter, like `product-id`, add it to [`data-allow-params`]({{ site.url }}/allow-params) first. It's only collected from then on.
- **No personal data:** never put email addresses, names, user IDs or other personal data in paths, URL parameters, [events]({{ site.url }}/events) or [metadata]({{ site.url }}/metadata). It's not allowed, and the account might be suspended.
- **Missing data,** for example because of ad blockers? Set up a [custom domain]({{ site.url }}/bypass-ad-blockers), or even better the [proxy]({{ site.url }}/proxy).

## How the data works

- **Visitors are [unique pageviews]({{ site.url }}/explained/unique-visits),** not people. A page view is unique when it has no referrer or comes from another website. We use no cookies or identifiers, so websites need no cookie banner.
- **Each step of a [goal]({{ site.url }}/goals) counts the matching data on its own.** Visitors don't have to go through the earlier steps, so a later step can be higher than an earlier one.
